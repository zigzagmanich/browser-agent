# Автономный браузерный агент — инструкция для работы над проектом

Тестовое задание (текст — `TASK.md`, лежит локально, в репозиторий не идёт): агент получает задачу текстом в
терминале и выполняет её в настоящем видимом браузере, сам решая, что нажимать.

- Репозиторий: https://github.com/zigzagmanich/browser-agent (публичный, ветка
  `main`, `gh` авторизован под zigzagmanich). Перед каждым коммитом — поиск
  личных данных пользователя (адреса, работодатели, контакты, отправители
  писем): в репозиторий они не идут. `TASK.md` (текст ТЗ компании) и `runs/`
  (логи с письмами и резюме) — в `.gitignore`, не коммитить.
- Для людей — `README.md`.
- Полный дневник исследования — `docs/RESEARCH.md`: находки 1–45 и прогоны 1–26
  с цифрами до и после, эксперименты, отвергнутые решения. **Новые находки и
  прогоны дописывать туда** (продолжая нумерацию), сюда — только то, что
  меняет правила работы.

## Жёсткие ограничения ТЗ (нарушение = провал задания)

- Никаких заготовленных сценариев: агент планирует каждый шаг в моменте.
- Никаких преднаписанных селекторов и упоминаний конкретных сайтов в коде и
  промптах. Правило индексатора, упоминающее сайт, — неверное.
- Никаких подсказок про адреса и тексты кнопок. `navigate` проверяется кодом:
  главная сайта, ссылка, которую сайт показал в сессии (параметры убрать можно,
  дописать нельзя), адрес из слов пользователя. Планировщику запрещено писать
  адреса, кнопки и маршрут.
- Видимый браузер, persistent-профиль (`~/.browser-agent/profiles/`).
- Обязательны: управление контекстом (целые страницы в модель не уходят),
  под-агенты, адаптация при ошибках, подтверждение деструктивных действий.

Проверка на честность: убрать из промптов всё про сайты — агент должен работать.

## Структура

```
main.py                 диалог в терминале; Ctrl+C прерывает задачу, а не программу
run.command|bat|sh      запуск в отдельном окне (macOS | Windows | Linux)
agent/orchestrator.py   цикл, планировщик перед циклом, бюджет шагов, детектор зацикливания
agent/tools.py          инструменты, резолв ref -> локатор, правила переходов, детекторы
agent/subagents.py      reader · classifier · writer · planner
agent/security.py       security gate: префильтр + guard-модель + вопрос человеку
agent/context.py        схлопывание снапшотов пачкой, журнал remember
agent/llm.py            вызовы Anthropic, кеш, учёт стоимости, модели по умолчанию
agent/runlog.py         запись прогона в runs/*.jsonl (личные данные — не коммитить)
agent/ui.py             вывод, строка ввода (prompt_toolkit), вопросы человеку
browser/session.py      контекст, вкладки, системные окна, видимые фреймы, snapshot(), type_text()
browser/dom_index.js    ЯДРО: DOM -> плоский список рефов
browser/page_state.py   рендер снапшота под бюджет токенов, chunk_text
prompts/orchestrator.md системный промпт — без названий сайтов
probe.py                стенд восприятия без LLM
replay.py · gate_eval.py · writer_eval.py · tests/
```

## Как агент видит страницу

`dom_index.js` инжектится в каждый видимый фрейм и отдаёт плоский список
видимых интерактивных элементов с номерами `[17]<button> Удалить`. Составная
запись (строка списка, карточка) — один реф с текстом в имени. Модель отвечает
номером, клик — `frame.locator('[data-agent-ref="17"]')`; рефы живут один
снапшот. Снапшот: элементы и текст на экране → «внутри прокручиваемого блока, за
его краем» → «вне видимой области» (сжато, 25% бюджета) → «…ещё N ниже».

## Правила работы

- **Сначала диагноз, потом код.** Перед правкой восприятия — `probe.py` на
  живом сайте (`snap`, `raw ПОДСТРОКА`, `struct REF`, `find CSS`,
  `find text=…` с «носителем курсора»), цифры до и после. Гипотеза должна
  подтверждаться данными (лог прогона, стенд), а не догадкой: две гипотезы
  этого проекта опроверг стенд.
- Правило индексатора — в терминах ролей, тегов и вычисленных стилей.
- Снапшот упёрся в бюджет — сначала искать дублирование, потом поднимать бюджет.
- Каждая правка — тест в `tests/` на синтетической странице, воспроизводящей
  вёрстку; прогнать весь набор (`./venv/bin/python -m pytest -q`, ~1 мин).
- Агент и стенд используют один код (`BrowserSession.snapshot()`,
  `BrowserSession.type_text()`) — не заводить копий: копия стенда уже отставала.
- Правка промпта проверяется `replay.py --step N`, а не полным прогоном.
- Нашёл ошибку — ищи весь её класс и закрывай заранее, а не только этот случай
  (пример: «адрес по памяти» → любые факты по памяти, дата, остатки прошлых
  задач; см. `docs/RESEARCH.md`).
- Находку или прогон — в `docs/RESEARCH.md` с цифрами; решения, меняющие
  правила, — сюда.

## Бюджет пользователя

API-бюджет ограничен; финальную полную проверку делает сам пользователь.
Платный прогон — только с конкретным вопросом, после бесплатных проверок; перед
ним назвать ожидаемую стоимость и дать готовую команду одной строкой.
Пользователь гоняет `probe.py` сам и сохраняет вывод в `~/Desktop/данные.docx`
(читать: `textutil -convert txt -output <scratchpad>/x.txt ~/Desktop/данные.docx`).
Ключ из `.env` не читать и не печатать.

| что проверяем | чем | цена |
|---|---|---|
| восприятие живых страниц | `probe.py` | 0 |
| механика агента | `pytest` (89 тестов) | 0 |
| политика gate | `gate_eval.py` | < 1¢ |
| писатель не выдумывает | `writer_eval.py` | < 1¢ |
| одно решение модели | `replay.py runs/<лог> --step N` | $0.01–0.05 |
| задача целиком | `main.py --task "..." --once` | $0.1–0.9 |

## Модели

По умолчанию Sonnet 5 исполняет, Opus 5 — планировщик (один вызов с
критериями задачи), Haiku 4.5 — под-агенты и guard-модель. Sonnet один
проваливал задачи на суждение (спам 0 из 5), с планом — справился; навигацию
ведёт не хуже Opus в 2–3 раза дешевле. Переменные: `ORCHESTRATOR_MODEL`,
`PLANNER_MODEL` (пусто — выключен), `WORKER_MODEL`.

## Состояние и открытые кандидаты

Все сценарии ТЗ пройдены живыми прогонами; витрина незнакомых сайтов —
Островок, Fandom, Dotabuff (таблицы — в README). Осталось: демо Лавки дословно
по ТЗ (веб-версия не показывает сохранённые адреса — проверить подсказки поля
адреса в probe). Демо-видео снято (2026-09-13), ссылка — в начале README (Google Диск);
ссылка на репозиторий отправляется проверяющим.

Открытые кандидаты — чинить, когда всплывут:
- безымянные иконки (`<button>` с голым svg) — точечное зрение по одной кнопке;
- пары «`<label>` + безымянный `<input>`» у фильтров-отметок — ~230 токенов на
  снапшот (Островок, окно добавок на сайте еды);
- ячейка дня в календаре подписана только числом — однажды промах на 10 дней;
- детектор трёх одинаковых вызовов сравнивает вместе с `ref`;
- `read_link` по строке списка без ссылки — ошибка инструмента;
- ответ 429 и антибот-экраны не покрыты; Linux не проверен вживую (macOS и Windows —
  работают; на Windows — только в Windows Terminal, старая консоль рисует кириллицу криво).
